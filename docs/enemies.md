# Lua 自訂敵人（技術原型）

敵人是一張**擁有 HP 的怪獸卡**。敵方不是玩家：沒有 LP、沒有牌組，HP 歸零就代表該單位死亡。

攻守、表示形式、效果、連鎖、攻擊宣告都交給 ygopro-core 原本的流程處理。這次**沒有新增任何核心修改**；專案原有的卡片實例 ID 補丁維持不變，見 [battle-module.md](battle-module.md#對核心的修改)。

這是技術原型：只驗證一隻敵人，數值都是測試值。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `game/data/enemies/c<卡號>.lua` | 一隻敵人：卡片資料加上效果，範例是 `c990000001.lua`（岩殼守衛） |
| `game/data/enemies/ygopve_enemy.lua` | 所有敵人共用的規則：HP、守備時的傷害、效果傷害、敵方沒有 LP |

## 定義一隻敵人

```lua
local s,id=GetID()

s.ygopve_enemy={          -- 由戰鬥模組讀取，當作核心的卡片資料
	name="岩殼守衛",       -- 必填
	text="……",            -- 選填：卡片說明
	atk=1200, def=2000,    -- 必填：原本攻擊力、守備力
	level=4, race=RACE_ROCK, attribute=ATTRIBUTE_EARTH, -- 選填，預設 0
}

function s.initial_effect(c)
	YgoEnemy.Init(c)       -- 套用敵人規則（HP 等）
	-- 其他效果照一般卡片腳本寫，例如 1 回合 1 次的速攻效果
end

function s.ai(c, prompt)   -- 行動模式：輪到敵方選擇時呼叫，見下方「敵人的行動」
	if prompt.type == "SELECT_IDLECMD" then
		return YgoEnemy.Find(prompt, "activate", c) or YgoEnemy.Find(prompt, "end")
	end
end
```

- **卡號**：
  - 由檔名決定，例如 `c990000001.lua` 的卡號是 990000001。
  - 卡號已經存在於卡片資料庫時，載入會直接失敗。
  - 測試敵人目前使用 9 億號段，正式的號段還沒決定。
- **卡片種類**：一律是效果怪獸。
- **讀取 `s.ygopve_enemy` 時**：模組只載入 `constant.lua`，可以使用 `RACE_*`、`ATTRIBUTE_*` 等常數，但不能呼叫核心函式。
- **`s.initial_effect`**：裡面的程式只有核心會執行，所以照一般卡片腳本的寫法即可。

## 誰載入、誰執行

```
Content（建立時）
  └─ 為每個 c<卡號>.lua 建立一個獨立的小型 Lua 環境，讀出 s.ygopve_enemy
     → 變成 CardData，之後核心要求卡片資料時直接提供，不需要 .cdb
Duel（建立時）
  └─ 載入 constant.lua、utility.lua，接著載入 ygopve_enemy.lua
  └─ 建立卡片時，核心照一般流程載入 c<卡號>.lua，並執行 initial_effect → YgoEnemy.Init
決鬥中
  └─ 核心執行規則效果與敵人效果
  └─ ygopve_enemy.lua 透過 Debug.Message("YGOPVE_HP ...") 回報 HP
     → 模組的 log 回呼接收，產生 Hp 事件，可以用 Duel::hp(instance) 查詢
```

- **兩個 Lua 環境各司其職**：
  - 模組自己的 Lua 只用來讀取資料，讀完就關閉。
  - 敵人效果只在核心的 Lua 裡執行。
  - 模組使用和核心同一份 Lua 原始碼，`build.ps1` 會一起連結進來。
- **敵人的決策**：寫在同一個檔案的 `s.ai`，見下一節。

## 敵人的行動

敵人的行動模式寫在 Lua 裡，方便之後開放給其他開發者設計。

### 誰呼叫、在哪裡執行

```
敵方要回答提示（核心暫停，等待回答）
  └─ 宿主呼叫 Duel::script_decide()
     └─ 模組把提示轉成 Lua 表格，用 OCG_LoadScript 在核心的 Lua 環境中執行
        YgoEnemy.Decide(prompt)
        └─ 依序詢問相關敵人的 s.ai(c, prompt)，第一個有回答的為準；
           都沒有回答時，用 YgoEnemy.DefaultDecide
        └─ 用 Debug.Message("YGOPVE_ANSWER ...") 回傳選項
  └─ 宿主照一般流程 submit() 這個答案
```

- **只能查詢，不能操作**：
  - 核心從外部執行程式碼時，本來就會禁止任何動作。如果在 `s.ai` 裡呼叫 `Duel.Destroy` 這類函式，會得到 `Action is not allowed here.`，模組也會停止這場決鬥並回報錯誤（已實測）。
  - 查詢函式都可以用，例如 `Duel.GetAttacker()`、`c:GetAttack()`、`Duel.GetLP()`、`YgoEnemy.GetHP(c)`，寫法和卡片腳本相同。
- **決策和效果處理是分開的**：
  - `s.ai` 只負責「選哪個選項」。
  - 選了之後的效果、連鎖、對方的回應，全部由核心照一般流程處理。
- **答案不合法時**：例如選項不存在，或核心拒絕這個答案，決鬥會以錯誤結束，不會改用其他答案。

### 寫法

- **`s.ai(c, prompt)`**：
  - 參數 `c` 是這隻敵人的卡片。
  - 回傳選項索引（從 1 開始）；需要選多張時，回傳索引清單。
  - 回傳 `nil` 或 `false` 代表「不決定」。
- **`prompt` 的內容**：
  - `type`：核心的提示名稱，例如 `SELECT_IDLECMD`、`SELECT_BATTLECMD`、`SELECT_CHAIN`、`SELECT_CARD`、`SELECT_EFFECTYN`。
  - 其他欄位：`player`、`min`、`max`、`forced`、`card`。
  - `options`：每個選項有 `action`（`activate`、`summon`、`repos`、`attack`、`battle`、`end`、`pass`、`card`、`yes`、`no` 等）、`card`（卡片物件）和 `code`。
- **輔助函式**：
  - `YgoEnemy.Find(prompt, action, card)`：找出第一個符合的選項。
  - `YgoEnemy.Best(prompt, 評分函式)`：找出卡片分數最高的選項。
  - `YgoEnemy.GetHP(c)`：查詢敵人目前的 HP 和上限。
- **詢問順序**：
  1. 和這個提示直接相關的敵人：正在發動或處理效果的那隻、正在攻擊的那隻。
  2. 場上其他表側表示的敵人，由左到右。
  3. 都沒有回答時，用預設行為。
- **預設行為**（測試規則）：能攻擊就進入戰鬥並攻擊；不發動選發效果、不連鎖；其他提示選第一個。

### 範例：岩殼守衛的行動模式

| 時機 | 行動 |
| --- | --- |
| 自己的回合 | 能發動效果就發動，對象是攻擊力最高的怪獸 |
| 自己的回合，HP 高於一半 | 轉成攻擊表示，攻擊攻擊力最低的怪獸 |
| 自己的回合，HP 一半以下 | 轉成守備表示，不攻擊 |
| 對手的回合，自己被攻擊時 | 發動效果，讓攻擊怪獸的攻擊力下降，減少損失的 HP |

這只是用來示範寫法的行動模式，還沒有考慮平衡，例如它會去攻擊比自己強的怪獸。

### 宿主怎麼使用

- **模擬器**：情境檔加上 `enemy_ai 1`，1 號玩家的所有提示都交給敵人腳本回答。
- **Godot**：開戰時傳入 `session.start(content, config, {"script_players": [1]})`。
  - 敵方的提示在 `step()` 裡就會自動回答，畫面只會看到玩家自己的提示。
  - 測試宿主的「敵人原型（P1 由敵人腳本行動）」按鈕就是這樣開戰的。

## 對應關係

| 敵人定義 | 執行時的狀態 | 核心裡的物件 |
| --- | --- | --- |
| 卡號、名稱、攻守、等級、種族、屬性 | `Content` 的快取（`CardData`） | 卡片資料，由 card reader 回呼提供 |
| `initial_effect` 裡的效果 | — | 卡片的效果，可以被連鎖、被無效 |
| HP 上限 | `ygopve_enemy.lua` 的表格，以卡片實例 ID 為索引；`Duel::hp()` | — |
| 目前 HP | 同上，用 `Hp` 事件通知宿主 | — |
| 守備時扣 HP、不會被戰鬥破壞 | — | 規則效果：`EFFECT_INDESTRUCTABLE_BATTLE`，有條件，加上 `EVENT_BATTLED` 時扣 HP |
| 攻擊表示時被攻擊，不比較攻擊力 | — | 規則效果：`EFFECT_SET_ATTACK_FINAL`，只在這次戰鬥的傷害步驟中把攻擊力設為 0 |
| 敵方沒有 LP | 敵方 LP 固定不變 | 全域效果：`EFFECT_CANNOT_LOSE_LP`、`EFFECT_AVOID_BATTLE_DAMAGE`，加上 `EVENT_DAMAGE` 時把 LP 設回原值 |

規則效果都帶有 `EFFECT_FLAG_CANNOT_DISABLE` 和 `EFFECT_FLAG_UNCOPYABLE`：無效敵人的效果時，HP 規則仍然有效，也不會被複製。

## 規則

| 情況 | 處理方式 | 狀態 |
| --- | --- | --- |
| HP 初始值 | 原本攻擊力加原本守備力 | **測試值** |
| 之後攻守被永續效果改變 | 傷害計算使用當下的攻守，HP 上限不變 | 已決定 |
| 敵人守備表示，攻擊方攻擊力大於守備力 | 敵人扣差額 HP，不會被戰鬥破壞；HP 歸零時才算擊敗 | 已決定 |
| 攻守相等 | 雙方都不受傷害，沿用原規則 | 已決定 |
| 攻擊方攻擊力小於守備力 | 敵人不扣 HP，攻擊方玩家受到差額傷害，攻擊怪獸不會被破壞，沿用原規則 | 已決定 |
| 戰鬥中 HP 歸零 | 由核心正常進行**戰鬥破壞** | 2026-10-06 決定 |
| 用效果移除敵人（落雷、送墓、除外等） | 照一般怪獸處理，不看 HP，屬於效果破壞或效果移除 | 2026-10-06 決定 |
| 給予敵方的效果傷害 | 扣敵人的 HP；HP 歸零時以**效果破壞**處理 | 2026-10-06 決定 |
| 敵人攻擊表示時被攻擊 | 不比較敵人的攻擊力：敵人扣「攻擊怪獸的攻擊力」那麼多 HP；攻擊怪獸不會被破壞，玩家也不受傷害；HP 歸零時被戰鬥破壞 | 2026-10-06 決定 |
| 敵人攻擊攻擊表示的怪獸，攻擊力相同 | 玩家的怪獸照原規則被破壞；敵人扣那隻怪獸的攻擊力那麼多 HP，HP 歸零才被戰鬥破壞 | 2026-10-06 決定 |
| 敵人攻擊攻擊表示的怪獸，敵人攻擊力較低 | 玩家的怪獸不被破壞；敵人扣差額 HP，HP 歸零才被戰鬥破壞 | 2026-10-06 決定 |
| 敵人攻擊守備表示的怪獸，守備力比敵人攻擊力高 | 原規則是攻擊方受到差額傷害；敵方沒有 LP，所以目前不扣 HP | **未定案** |
| 有多隻敵人時，效果傷害扣誰 | 扣場上序號最小（最左邊）的那隻 | **測試值** |
| 貫穿傷害、直接攻擊敵方 | 戰鬥傷害一律變成 0；貫穿的部分已經算在扣 HP 的差額裡 | 原型的處理方式 |

### 擊敗時使用的核心處理與觸發語意

攻擊表示時被攻擊：傷害步驟中敵人的攻擊力是 0，所以核心比較的是「攻擊怪獸的攻擊力對 0」。之後的流程和守備時相同，HP 歸零一樣是真正的戰鬥破壞。副作用是：傷害步驟中，其他卡查到的敵人攻擊力也是 0。

- **戰鬥中 HP 歸零**：
  - 做法：在傷害計算時，核心會詢問「不會被戰鬥破壞」效果是否適用；這次傷害足以讓 HP 歸零時，這個效果就不適用。
  - 結果：核心照一般的戰鬥破壞流程處理，原因是 `REASON_BATTLE | REASON_DESTROY`。
  - 會觸發的效果：「被戰鬥破壞時」、「戰鬥破壞對方怪獸時」、送墓、離場。
  - 只會結算一次：破壞由核心進行，HP 只在傷害計算結束後扣一次。
- **戰鬥中 HP 沒有歸零**：
  - 不會被破壞，沒有送墓、沒有離場，也不會觸發上述效果。
  - 但「傷害計算後」（`EVENT_BATTLED`）類的效果照常觸發。
  - 核心會送出一個卡片提示，說明是哪張卡讓敵人沒有被破壞。
- **效果傷害讓 HP 歸零**：
  - 處理方式：`Duel.Destroy(敵人, REASON_EFFECT, 墓地, 造成傷害的玩家)`。
  - 原因：`REASON_EFFECT | REASON_DESTROY`。
  - 「破壞原因的效果」是敵人規則的全域效果，不是造成傷害的那張卡。所以「被對方的效果破壞」看玩家的條件會成立，但「被某張卡的效果破壞」看卡片的條件不會成立。
- **用效果移除**：完全是核心原本的處理，例如落雷是 `REASON_EFFECT | REASON_DESTROY`。

## 已知限制

- **`s.ai` 只在敵方需要回答提示時才會被呼叫**：敵人不能在沒有提示時主動做事。
  - 目前範例：敵人只在被攻擊時發動效果。
  - 不一定能做到的情況：要在對手的其他時機回應，例如對手發動效果時，就只能等核心給敵方連鎖窗口。
- **預告下一次行動**：還沒做；TODO 中仍待決定。
- **敵方的 LP 仍然存在**：核心的決鬥固定是兩位玩家，所以敵方 LP 仍然存在，只是固定不變。
  - 畫面上會顯示 `LP 8000`。
  - 會參照「對方 LP」的卡片看到的也是這個值。
- **HP 歸零卻沒有被破壞**：如果有其他效果讓敵人不會被戰鬥破壞或效果破壞，HP 會停在 0，敵人留在場上。這種情況還沒有定義怎麼處理。
- **敵方要從空牌組抽牌時**：敵方每回合抽 0 張。如果效果讓敵方從空牌組抽牌，結果沒有測試過。
- **還沒測試的情況**：敵人變成裡側、被奪取控制權、離場後再回到場上（回場會被當成新單位，HP 重新計算）。
- **一次戰鬥只扣一次 HP**：扣多少 HP，是在核心判定是否破壞時記下來的數字，傷害計算結束後才扣。同一次傷害計算中，如果核心重複詢問，會覆蓋成同樣的數字。
- **HP 事件的順序**：HP 事件是在同一批核心訊息處理完之後才加進去的，所以在紀錄裡會排在那一批訊息的最後。
- **被無效的敵人效果仍會出現在發動選項中**：這是核心原本的行為，不是我們造成的。
