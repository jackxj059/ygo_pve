# 道具與裝備

規格與待定事項見 [items-equipment.md](items-equipment.md)。本文件說明目前的實作方式、Lua 接口、四項技術驗證的結果，以及支援範圍。

- **第一階段（技術驗證）**：已完成。
- **第二階段（最小功能）**：已完成。在 Godot 測試宿主可以戰外配置裝備、戰鬥中使用道具，道具與裝備由測試資料配給。掉落、素材與合成還沒有做。

**核心修改**：沒有新增任何核心補丁。專案原有的卡片實例 ID 查詢補丁（`0001-query-cardid.patch`）仍然是依賴：裝備綁定與免 AP 都靠卡片實例 ID 運作。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `game/data/support/ygopve_support.lua` | 道具與裝備共用的規則：開局處理、道具窗口、結果回報、裝備綁定、「洗回牌組」的共用操作 |
| `game/data/items/c9900003xx.lua` | 範例道具：回收之鈴（除外區 5 張洗回）、墓地回收網（墓地 5 張洗回）、回復藥（回復 1000） |
| `game/data/equipment/c9900002xx.lua` | 範例裝備：省力徽章（發動免 AP）、雙擊徽章（戰鬥傷害 2 倍）、回復徽章（原效果成功後回復 1000） |

道具與裝備和敵人一樣，都是 `c<卡號>.lua`，定義寫在 `s.ygopve`，分別用 `kind="item"` 和 `kind="equip"`。模組會讀取自訂卡片資料夾（`game/data`）底下的所有子資料夾。

## Lua 接口

一個道具或一件裝備就是一個 `c<卡號>.lua`，定義表用 `s.ygopve`。

**道具**：

```lua
local s,id=GetID()
s.ygopve={ name="回收之鈴", kind="item", text="……" }

function s.initial_effect(c)
	YgoSupport.Item(c, s.condition, s.operation)
end
-- 現在能不能用（窗口規則之外的條件）；nil 代表沒有額外條件
function s.condition(e,tp) return Duel.IsExistingMatchingCard(YgoSupport.CanShuffle,tp,LOCATION_REMOVED,0,5,nil) end
-- 實際執行，回傳 "success"、"partial"、"nochange" 或 "cancel"（nil 視為 success）
function s.operation(e,tp) return YgoSupport.ShuffleIntoDeck(tp,LOCATION_REMOVED,5) end
```

**裝備**：

```lua
s.ygopve={ name="省力徽章", kind="equip", text="……", ap_free={"activate"} } -- ap_free 由戰鬥模組處理
function s.initial_effect(c)
	YgoSupport.Equip(c, s.install)        -- install 可以省略
end
function s.install(tc, owner, eq)        -- 開局時對裝備的那一張卡註冊效果一次
	local e1=Effect.CreateEffect(tc)
	e1:SetProperty(YgoSupport.RULE)        -- 不會被無效、不會被複製
	...
	tc:RegisterEffect(e1)
end
```

**共用函式**：
- `YgoSupport.ShuffleIntoDeck(tp, 區域, 張數)`：選卡後洗回牌組，回傳結果。
- `YgoSupport.CanShuffle(c)`：這張卡能不能被選；除外區只算表側。
- `YgoSupport.RULE`：裝備效果用的屬性，讓效果不會被無效、也不會被複製。

**錯誤處理**：
- `kind` 寫錯、`ap_free` 寫了不存在的動作、同一個卡號出現在兩個檔案、少了共用規則檔，載入時都會報錯。
- 執行時的 Lua 錯誤，會讓決鬥以錯誤結束。

**戰鬥設定**（`YgoDuel.start` 的 config，或模擬器的 `item`／`equip` 行）：

```gdscript
"items": [{"player": 0, "code": 990000303, "count": 2}],
"equipment": [{"player": 0, "source": "main", "index": 3, "code": 990000202}],  # 主牌組清單的第 4 張
```

## Godot 測試宿主

1. 主選單選「預覽牌組」。
2. **戰外配置**：點主牌組或額外牌組的任一張卡，從選單裝上或拿下裝備。
   - 每張卡只能裝一件，同名卡分開算。
   - 裝備的數量由 `host/test_settings.gd` 的 `EQUIPMENT` 配給。
3. 選「開始戰鬥」：對手可以選 test_basic.ydk（手動操作），或岩殼守衛（敵人自動行動，可以測試對敵人 HP 的 2 倍傷害）。
4. **戰鬥中**：
   - 在自己的主要階段，右側會出現「使用道具：名稱（剩 N）」；用完會標成「已用完」。
   - 紀錄會顯示「使用道具 X：成功／部分成功／沒有變化／取消（不消耗）」。
   - 裝了裝備的卡，在場上和手牌時左上角有「裝」字，滑鼠移上去會顯示裝備名稱。
5. 道具由 `TestSettings.ITEMS` 配給，每一場測試對戰都會帶上。

**畫面重掛與新的 session**：
- 裝備在建立決鬥時由戰鬥模組安裝一次。畫面卸下再掛上，只是重新顯示，不會重新安裝。
- 每個新的 session 都是一場新決鬥，各自安裝一次。

## 驗證 1：道具不開連鎖

**核心允許的執行入口**：玩家層級的「場地持續效果」，觸發條件是 `EFFECT_TYPE_FIELD | EFFECT_TYPE_CONTINUOUS` 加上 `EVENT_FREE_CHAIN`。EDOPro 的 Speed Duel 技能就是用這種寫法。

- **主要階段**：核心把它列在主要階段的發動選項裡；選了之後，核心直接用 `solve_continuous` 執行，**不建立連鎖鏈結**，對手也沒有回應的時機（`processor.cpp` 的 IdleCommand 第 1 步）。
- **可以真的做事**：執行時是一般的核心處理，所以可以移動卡片、回復 LP、讓玩家選卡。

  這和敵人決策的入口不同：敵人決策用 `OCG_LoadScript` 在核心等待回答時執行，核心會擋下所有動作，所以那裡不能用來做道具。

- **戰鬥階段**：核心在戰鬥階段的選項裡也會列出這類效果，但道具的條件限制在主要階段，所以不會出現。
- **連鎖窗口**：核心在連鎖窗口也會列出這類效果，例如召喚後的回應時機。所以戰鬥模組會把道具從主要階段以外的所有提示中拿掉。拿掉之後如果只剩「不連鎖」，模組就自動略過，玩家不會看到多餘的提示。
- **道具的卡片**：
  - 道具在核心裡是一張卡。模組開局時把它建立在擁有者的手牌。
  - 決鬥開始時（`EVENT_STARTUP`），共用規則替擁有者註冊道具效果，再用 `Duel.SendtoDeck(c, tp, -2)` 把卡移出決鬥。
  - 所以它不在任何區域、不會被抽到，也不會被當成手牌。

**結果回報**：
- 道具操作回傳 `success`、`partial`、`nochange` 或 `cancel`，透過 `Debug.Message("YGOPVE_ITEM …")` 回報。模組轉成 `Item` 事件。
- 另外兩種結果不經過道具本身：
  - **拒絕**：選項不存在、過期或重複的提示 ID。由模組的提示機制處理，請求不會送進核心。
  - **錯誤**：Lua 錯誤。決鬥會以錯誤結束，不會宣稱已經還原。

| 測試 | 結果 |
| --- | --- |
| `items/item_recover` | 回復藥沒有建立連鎖鏈結，LP 5000 → 6000。之後 Fire Princess（持續效果）造成 500 傷害；Aromage Jasmine 的必發誘發效果正常建立自己的連鎖並抽 1 張。之後可以繼續一般操作。數量 2 的道具用完兩次後，選項標成不能選 |
| `items/item_recycle` | 選卡時取消，回報 `cancel`，卡片都沒有移動，數量也沒有減少。選 5 張（含 1 張融合怪獸），回報 `success`：主牌組 +4，融合怪獸回到額外牌組，數量變成 0 |
| `negative/item_needs_five` | 墓地只有 4 張時，不會出現這個道具 |
| `negative/item_facedown_excluded` | 除外區只有 4 張表側卡，其餘 10 張是裡側時，不會出現這個道具 |
| `negative/item_not_in_battle` | 戰鬥階段不會出現這個道具 |
| `negative/item_not_in_chain` | 自己主要階段的連鎖窗口中，也不會出現這個道具 |

## 驗證 2：指定卡片免 AP

**綁定方式**：
- 裝備用卡片的「外部固定 ID」指定目標：哪位玩家的主牌組、額外牌組或固定配置的第幾張（`CardOrigin`）。
- 開局時，模組把這個位置對應到核心的卡片實例 ID。
- 核心的卡片實例 ID 在整場決鬥中不會變：換區域、蓋回、復活都還是同一張卡。所以綁定不會因為位置改變而錯亂，也不需要用事件位置回頭查卡片。

**計價**：在戰鬥模組的 `price_options` 中，如果選項的卡片實例有裝備免除這種動作，費用就是 0。顯示的費用、能不能選、確認後實際扣的 AP，都用這同一個數字。

| 測試 `equipment/equip_ap_free` | 結果 |
| --- | --- |
| 同名的 3 張貪欲之壺，其中 2 張裝備 | 沒裝備的那張花 1 AP；裝備的在 0 AP 時仍然可以發動，而且不扣 AP |
| 連鎖發動 | 在對手回合的連鎖窗口中，以 0 AP 發動裝備的那張 |
| 其他動作 | 裝備的 Goblindbergh 通常召喚仍然花 1 AP；從手牌移到場上後，它的效果仍然免費 |
| 道具 | 道具不花 AP（2026-10-07 決定） |

## 驗證 3：戰鬥傷害 2 倍

**裝備**：雙擊徽章在目標卡片上註冊核心的 `EFFECT_CHANGE_BATTLE_DAMAGE`，值是「對這張卡當下控制者的對手造成的傷害為 `DOUBLE_DAMAGE`」，也就是給對手的傷害變成 2 倍。不會改攻擊力。2 倍、減半、多個 2 倍同時存在時怎麼合併，都照核心規則處理。

**敵人 HP 的計算方式（2026-10-07 確認保留）**：為了讓 HP 也照核心的倍率計算、而且只算一次，敵人扣 HP 的數字來源改成：
- **以前**：Lua 自己用攻擊力減守備力等公式算。
- **現在**：直接讀核心這次算出的敵方戰鬥傷害（`Duel.GetBattleDamage`）。
  - 守備表示被攻擊時，給攻擊方怪獸貫穿，核心才會把差額算成傷害。
  - 敵方的 LP 改用「戰鬥傷害變成 0」保護。原本用的是「不受戰鬥傷害」，那樣核心根本不會算出這個數字。
- **不變的部分**：攻擊表示被攻擊時，攻擊力暫時設為 0 的做法照舊。
- **結果**：原有的 11 個敵人測試全部照舊通過，數字完全相同。
- **例外**：敵人主動攻擊、攻擊力相同時，扣的是規則值（對方攻擊力），不經過核心的傷害計算，所以倍率不適用。

原則：敵方 HP 的增減，一律以核心算出的傷害為準，Lua 只負責把傷害轉到 HP。不改 Lua 的另一條路只有改核心，因為戰鬥模組只能在核心判定完破壞之後才收到結果，那時只能事後補做破壞。

| 測試 | 結果 |
| --- | --- |
| `equipment/equip_double_damage`（一般對戰） | 裝備的 1400 打 800 造成 1200；同名沒裝備的造成 600；裝備的 800 打 800 是 0；Susa Soldier（本身減半）裝備後，2 倍和減半互相抵消，造成 600；裝備的 Warwolf 從墓地復活後（換區域）照樣 2 倍，造成 2400 |
| `equipment/equip_double_stack` | Piranha Army 直接攻擊時本身就是 2 倍，裝備後仍然是 1600，不會變 4 倍 |
| `equipment/equip_control` | 對手用心變奪走裝備的凱爾特直接攻擊，1400 × 2 = 2800 打在原本的擁有者身上（效果跟著卡） |
| `equipment/equip_double_enemy`（敵人 HP） | 沒裝備的黑魔導 2500 打守備力 2000 扣 500，裝備的扣 1000（規格的例子）。Susa 打稻草人扣 750（減半）。裝備的凱爾特打稻草人，900 × 2 = 1800，超過 HP 1500：在傷害計算時就判定戰鬥破壞（`reason=0x21`）。敵方 LP 一直是 8000 |

## 驗證 4：原效果成功後回復

**核心看得到的事件**（`processor.cpp` 的 SolveChain）：

| 情況 | 核心的事件 |
| --- | --- |
| 發動被無效 | `CHAIN_NEGATED`，之後**不會**送出 `CHAIN_SOLVED` |
| 效果被無效 | `CHAIN_DISABLED`，不執行操作，但**之後仍然會**送出 `CHAIN_SOLVED`。所以收到 `CHAIN_SOLVED` 不能直接當成成功 |
| 處理開始 | `CHAIN_SOLVING`。這時取對象效果的對象是否還有效，可以用 `IsRelateToEffect` 判斷 |
| 處理結束 | `CHAIN_SOLVED`。這之後核心才解除對象的關聯，所以處理途中被效果本身移走的對象，不會被誤判成「目標消失」 |

**有限支援的「成功」定義**：同一個連鎖鏈結，而且觸發效果的卡片就是裝備的那一張（比對卡片物件，不是卡號），並且同時符合：
1. 發動沒有被無效。
2. 效果沒有被無效。
3. 處理開始時，每個對象都仍然有效。
4. 發動的魔法、陷阱開始處理時仍在場上。

**回復時點**：在那個鏈結的 `CHAIN_SOLVED` 時，由場地持續效果執行 `Duel.Recover`。不會建立新的連鎖鏈結；回復造成的誘發效果，照核心規則在之後處理。回復給這張卡當下的控制者（2026-10-07 決定：跟著卡）。

| 測試 `equipment/equip_recover` | 結果 |
| --- | --- |
| 裝備的強欲之壺處理完 | +1000 |
| 同名沒裝備的強欲之壺 | 不回復 |
| 裝備的強欲之壺被神之宣告無效發動 | 不回復 |
| 裝備的 Goblindbergh 效果被無限泡影無效 | 不回復 |
| 裝備的死者蘇生，對象被 D.D. 烏鴉除外 | 不回復，也沒有特殊召喚 |
| 沒裝備的貪欲之壺與裝備的貪欲之壺在同一條連鎖 | 只回復 1 次 |

最後一項還順便驗證了被無效的情況：無限泡影的「同一直列的魔法陷阱無效」效果把沒裝備的那張無效了，裝備的那張不受影響，照樣回復。

## 支援範圍

### 已驗證

- 道具不開連鎖，可以選卡、取消，之後的效果照常處理。
- 道具只能在自己的主要階段使用，戰鬥階段和連鎖窗口都不能用。
- 回收時，張數不夠就不能使用；裡側除外的卡不能選；額外牌組的怪獸會回到額外牌組。
- 同名卡個別裝備。
- 免 AP：顯示、檢查和實際扣費一致；0 AP 時可以發動；連鎖時發動也免費；換區域後仍然有效。
- 傷害 2 倍：對玩家 LP 和敵人 HP 都有效；0 傷害不變；和減半互相抵消；不會和原卡的 2 倍疊加；致死時在傷害計算當下判定；換區域（復活）後仍然有效。
- 成功回復：正常處理、發動被無效、效果被無效、目標消失、同一條連鎖中有其他卡的鏈結，這幾種都分得清楚。

### 尚未驗證

- **回收的限制**：「不能回到牌組」（目前用核心的 `IsAbleToDeck` 過濾）、移動目的地被其他效果改掉（目前只計算實際到達牌組或額外牌組的卡），都還沒有實測。
- **裝備的狀態變化**：蓋回、效果被複製、卡名改變。控制權轉移只實測了倍傷（`equip_control`）。
- **回復的互動**：「不能回復」「回復轉成傷害」照核心規則處理，但還沒有實測。
- **傷害的組合**：反射傷害，以及敵人攻擊我方守備怪獸時的組合。
- **畫面相關**：重新開啟畫面不會重複安裝裝備，這是設計上的保證（裝備在建立決鬥時安裝），沒有另外寫自動測試。

### 不支援，或只能有限支援

- **只完成一部分的效果、延遲生效的效果**：核心沒有辦法告訴我們效果「做到了什麼」。例如效果要檢索卻沒有卡可以檢索，或效果處理完後才註冊之後才生效的效果，目前都會被判定為成功。之後需要針對個別效果寫專用判斷。
## 已決定的規則（2026-10-07）

- **道具**：
  - 不花 AP，而且是消耗品：開戰時給定數量（模擬器寫 `item P 卡號 x2`）。
  - 開始執行就算用掉一次，不論結果是成功、部分成功或沒有變化；選卡時取消、還沒送出，則不算。
  - 用完後選項會標成不能選，戰鬥模組也會拒絕。
  - 同一位玩家的同一種道具只能列一次，多個請寫數量。
- **回收**：額外牌組的怪獸算在 5 張之內。
- **裝備跟著卡**：控制權轉移後，免 AP、2 倍傷害（給「當下控制者的對手」）、回復（給當下控制者）都以當下的控制者為準。
- **裝備效果**：不會被無效，也不會被複製。

## 測試設定（尚未定案）

- 回復藥只回復使用者自己。介面保留了玩家 ID，可以之後擴充。
- 道具沒有另外限制每回合的使用次數。
