# 道具與裝備規格及驗證計畫

更新日期：2026-10-07。供 Claude 實作前使用；本階段先收斂例外與驗證接口，不包含掉落物、素材配方、角色成長或正式美術。

道具及裝備內容由 Lua 定義。共用接口管理合法性、個體識別與結算，不將特殊道具判斷散落到 GUI、session 或 C++。不新增 ygopro-core C++ 補丁；現有卡片實例 ID 查詢補丁仍須如實列為依賴。

## 已定案範圍

- 道具在戰鬥中主動使用，只限自己的回合，不開連鎖，不插入正在處理的效果。
- 範例用途：除外區五張卡洗回牌組、墓地五張卡洗回牌組、回復玩家 LP。
- 裝備在戰鬥外配置給某張具體卡片，可適用怪獸、魔法與陷阱；不是要抽到並發動的裝備魔法卡。
- 裝備範例：該卡發動免 AP、該怪獸造成的戰鬥傷害翻倍、原效果成功後附帶回復 1000 LP。
- 倍傷包含對玩家的 LP 傷害與對敵人的 HP 傷害；不代表受到的反傷或所有效果傷害也翻倍。
- 被無效的原效果不提供成功後回復；不能把連鎖結束等同效果成功。
- 單體回復介面保留玩家 ID，單人原型先驗證自己；多人仍非本階段交付。

## 規則決策表

「實作基準」為本次採用的原型邊界；「待定」不得由開發者自行改成正式規則。待定項目不阻擋其他技術驗證。

| 項目 | 處理 | 狀態 |
| --- | --- | --- |
| 道具窗口 | 自己主要階段、核心等待主要階段操作、沒有連鎖／選卡／其他操作待結算；受階段跳過等核心限制 | 實作基準 |
| 道具與連鎖 | 道具本身不成為連鎖鏈結；移動或回復所引起的原生事件不能一併封鎖 | 實作基準，需驗證正確執行入口 |
| 精確回收五張 | 選五張不重複且可處理的卡，不足則不能開始；「最多五張」需另外定義 | 實作基準 |
| 選卡取消 | 提交前可以取消，不扣庫存或 AP；執行後不能任意回滾核心 | 實作基準 |
| 選卡有效性 | 用卡片個體識別；提交時重新驗證所有權、區域、數量與合法性，不能僅驗卡號 | 實作基準 |
| 卡片移動限制 | 呼叫核心既有處理，尊重不能回牌組及移動替代；不得直接改場面列表 | 實作基準 |
| 額外牌組卡 | 交核心決定目的地，不能強制塞主牌組；算進「五張洗回牌組」的數量 | 已定案（2026-10-07） |
| 裡側除外卡 | 可見資訊與可選條件不能繞過；第一個回收原型先只支援表側卡 | 實作基準；全面支援待定 |
| 道具費用 | 不花 AP；道具是消耗品，開戰時給定數量；開始執行就算用掉一次（不論結果），提交選擇前取消不算 | 已定案（2026-10-07）；每回合次數未另外限制 |
| 部分成功 | 核心若只移動部分目標，要回報實際結果；不能自行補足或宣稱全成功；照樣算用掉 | 已定案（2026-10-07） |
| 裝備綁定 | 綁玩家卡片個體，不綁卡號；同名卡不可互相獲得裝備 | 已定案 |
| 跨區域 | 原則上保留配置關係；每項能力另定在哪些區域適用，不等於離場後效果永久適用 | 實作基準 |
| 控制權轉移 | 裝備的效果跟著卡：免 AP、倍傷、回復都以這張卡當下的控制者為準 | 已定案（2026-10-07） |
| 卡名改變／複製效果 | 不因變成同名或複製原卡效果而自動複製裝備配置 | 實作基準；效果複製互動需測試 |
| 欄位、拆卸與複數裝備 | 原型一次只測一件能力，不代表正式限制為一欄；疊加順序不得依載入順序 | 正式規則待定 |
| 卡片被無效 | 原效果無效則無附帶成功回復；裝備本身不會被無效 | 已定案（2026-10-07） |
| 回復 | 透過核心回復機制，尊重不能回復、回復轉傷害等效果；記錄實際結果 | 實作基準 |

## 現有程式接點與限制

| 位置 | 現況及接入要求 |
| --- | --- |
| `native/battle/battle.cpp` 的 `price_options`／`submit`／`charge_pending` | AP 費用標示、拒絕與實扣需使用相同的費用決策；目前並非 Lua 費用插件，需加整合接口 |
| 同檔的連鎖事件解析 | 有發動、開始處理、無效與整串結束事件，尚無可證明任意效果成功的結果模型；目前 `chain_` 只存卡號，不足以識別同名卡不同發動 |
| `game/data/enemies/ygopve_enemy.lua` | 已自訂 HP 與傷害計算；倍傷要接在 HP 決定是否戰鬥破壞之前，不能只在扣 HP 後補乘 |
| `YgoBattleSession` | 持有決鬥與轉交操作；可承接宿主命令，但不在此堆各道具的效果判斷 |
| 核心等待玩家回答的 Lua 環境 | 目前 AI 執行點只允許查詢，不能假設可在同一位置直接 `Duel.Recover` 或移動卡片；道具需驗證合法、可暫停的執行路徑 |
| 卡片 ID | 冒險中的卡片 ID 與本場核心 ID 分開映射；事件批次位置回查可能誤認同名卡，裝備不得依該近似資訊結算 |

## Lua 接口草案

以下是待實作的能力契約，不是現有函式。先提供一個註冊入口與少量能力接口，不建立任意事件都可修改戰局的通用腳本系統。

```lua
-- 示意，不可直接執行
Items.register {
    id = "recycle_grave_5",
    version = 1,
    window = "own_main_idle",
    selection = { zone = "grave", count = 5, owner = "user" },
    operation = "return_selected_to_deck_and_shuffle",
    params = {},
}

Equipment.register {
    id = "free_activation",
    version = 1,
    capability = "activation_ap_cost",
    params = { value = 0 },
}
```

### 道具執行契約

1. `prepare_use`：驗證窗口、庫存及可選目標，產生唯一請求 ID；不修改戰局。
2. `submit_use`：接收請求 ID 與選擇，拒絕重複、過期或無效的回答；執行期間鎖住其他玩家指令。
3. 共用執行器將操作接進核心允許的流程，處理選卡暫停及原生事件；GUI 只顯示與回覆。
4. 回報 `completed`、`partial`、`no_change`、`rejected`、`cancelled` 或 `error`，並附實際移動／回復資料。
5. 庫存消耗依確認後的政策集中結算一次。Lua 錯誤若發生於部分執行後，不得宣稱已回滾；終止或明確標記不完整狀態。

結果名稱與函式名可依實作調整，但各狀態不能混為單一布林值。

### 裝備生命週期與能力契約

- 戰外資料至少包含 `card_instance_id`、`equipment_instance_id`、`definition_id`、版本及參數。
- 開局建立 `card_instance_id → core_card_id` 對應，集中安裝效果；畫面重掛不得重複安裝。
- 卡片移動、蓋回、效果無效／恢復、控制權轉移時，依能力的明確作用範圍處理；不能一律重裝。
- 能用核心效果表達的能力在核心中執行；外部 AP 特例由統一費用接口處理。
- 第一版能力：發動 AP 費用覆寫、戰鬥傷害倍率、經驗證的原效果成功後回復。
- 能力不可判定或無合法接點時，必須回傳「不支援」及原因；正式流程阻擋該配置，不能靜默略過。

## 效果成功後回復

「未被無效」「鏈結處理完」「產生了某次回復／移動」皆不能單獨證明原效果成功。追蹤至少需要決鬥 ID、連鎖 ID、鏈結序號、來源卡片實例與效果識別，不可只靠卡號或整串 ChainEnd。

| 情況 | 處理要求 |
| --- | --- |
| 發動或效果被無效 | 不回復 |
| 目標消失或不再合法，原效果沒有執行 | 不回復 |
| 原效果全部完成 | 依配置回復一次 |
| 只完成部分效果 | 成功定義待定；無專用判斷前列不支援 |
| 延遲生效或註冊後續效果 | 待定成功時點，不在發動當下猜測 |
| 永續卡發動與其後主動效果 | 分開識別，不能因持續適用而重複回復 |
| 同卡多效果／同鏈多次發動 | 分開結算，各次只一次；複製效果不得誤用來源裝備 |

技術驗證先選能明確觀察結果的效果，驗證正常、無效、目標消失三種情境。通用接口若無足夠資訊，提出按效果建立適配器的有限支援方案，不修改所有官方腳本，也不降低使用者要求。

附帶回復應在原效果處理完成後的合法核心時點發生，而不是等整串連鎖結束才由 GUI 補 LP。具體時點、是否額外建立鏈結及對原生觸發的影響，必須在探針結果中說明。

## 戰鬥傷害倍率

- 核心 LP 傷害與自訂敵人 HP 可以有不同執行接點，但同一能力規格與倍率政策只有一份；每筆傷害只套用一次。
- 使用裝備怪獸當次造成的戰鬥傷害，非無條件把其攻擊力乘二。
- 敵方守備例：2500 ATK 對 2000 DEF，基礎差額 500，倍傷後扣 1000 HP。不得先倍攻再減防得到 3000。
- 傷害不超過 HP 但倍傷後致死時，核心必須在戰鬥破壞判定時知道，不可先允許存活再補做效果破壞。
- 基礎零傷害不因倍傷變成非零；不能穿透已適用的傷害無效。
- 反射、減半、多重倍傷、貫穿、敵方主動攻擊及我方守備時的互動，需逐項測試；無法保證的組合明列不支援。
- 既有「攻擊表示敵人傷害步驟 ATK 暫設 0」維持現階段接受的原型規則，不擴大此次重構。

## 測試矩陣

所有案例先列預期，再寫測試；待定規則不可先寫死預期當成決策。

| 群組 | 必測案例 | 驗收重點 |
| --- | --- | --- |
| 道具窗口 | 自己主要階段、敵方回合、戰鬥／傷害步驟、連鎖中、選卡中 | 只允許已確認窗口；錯誤時不耗資源 |
| 選取 | 五張、四張、重複選取、過期請求、取消、連點提交 | 數量與個體正確；只結算一次 |
| 回收 | 主牌組卡、額外牌組卡、不能回牌組、目的地替代、裡側除外 | 核心正確處理與診斷；不直接改區域列表 |
| 道具後續 | 回收／回復引起觸發、洗牌、之後繼續普通操作 | 道具不建鏈，但不吞掉合法觸發或破壞核心提示狀態 |
| 免 AP | 零 AP 發動、被無效、取消、同名未裝備卡、連鎖發動 | 顯示費用與實扣一致；只影響指定個體及發動 |
| 裝備生命週期 | 手牌→場上→墓地→復活、蓋回、洗牌、畫面重掛、新 session | 配置不串卡、不累加；無可靠識別不得假裝成功 |
| 成功回復 | 正常處理、發動無效、效果無效、目標消失、部分完成、延遲效果 | 成功定義可靠；無法判定明確不支援 |
| 回復互動 | 自己、有效友方、無效玩家 ID、不能回復、回復轉傷害 | 使用核心流程，不直接設定 LP |
| 倍傷 | 玩家 LP、敵人攻守表示 HP、零傷害、倍傷致死 | 同一次只乘一次；正確的破壞原因與事件 |
| 傷害組合 | 減半、反射、貫穿、原卡倍傷、多裝備 | 順序與支援範圍明確，不依載入順序 |
| 註冊與錯誤 | 重複定義 ID、未知能力、Lua 載入／執行錯誤、缺少資料 | 載入或執行明確失敗，不以殘缺效果繼續 |
| 回歸 | 既有 AP、Genesys、普通決鬥、敵人與 Godot 測試 | 既有能力不退步 |
