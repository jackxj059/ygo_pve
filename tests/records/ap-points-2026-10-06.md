# AP 與 Genesys 式構築點數測試紀錄（2026-10-06）

範圍：AP 執行規則、構築點數檢查。依 2026-10-06 的範圍調整，**成長和升級不在這次範圍內**。所有 AP 數值與構築上限都是外部傳入的**測試值**，不代表平衡決定。

## 這次確認的決策

- **點數表來源**：官方 TCG Genesys 點數表，只取點數，不帶卡池限制。
- **計分範圍**：主牌組加額外牌組，備牌不算。官方 Genesys 也會計算備牌，這點與官方不同。
- **沒列出的卡**：點數表內必須明確宣告預設值，官方表宣告為 0 點；沒宣告就拒絕載入。
- **反轉召喚**：算「手動變更表示形式」，與 `repos` 共用同一個費用。
- **測試對手**：不受 AP 限制。

## AP 驗收

| 驗收條件 | 情境 | 結果 |
| --- | --- | --- |
| AP 不足不會先支付卡片原有代價 | `ap/ap_blocked`、`negative/ap_not_enough` | 早すぎた埋葬（費用 2，只剩 1 AP）標為不能選，LP 維持 8000；硬送會被模組拒絕：`not enough AP (needs 2, has 1)` |
| 必發效果在 0 AP 時正常處理 | `ap/ap_mandatory_free` | 0 AP 時，Goblindbergh 的選發效果「是」被擋下；Sangan 的必發效果照常發動並檢索 |
| 死者蘇生只在發動時扣一次 | `ap/ap_basic` | 發動時扣 1 點，效果處理中特殊召喚青眼不收費；Goblindbergh 選發效果扣 1、它特殊召喚亞歷山大龍不收費 |
| 多次連鎖不超支、不重複扣費 | `ap/ap_chain` | 2 AP 時連鎖兩張 Jar of Greed，各扣 1 點；第三張標為不能選 |
| 回滿時機 | `ap/ap_basic`、`ap/ap_chain` | 自己回合開始時回滿；對手回合可以使用剩下的 AP，但不會回滿 |
| 被無效不退費 | `ap/ap_negated` | 死者蘇生被神之宣告無效，AP 維持在 0 |
| 取消不扣費 | `ap/ap_cancel` | 上級召喚時取消選擇解放，AP 不變；正式召喚時才扣 1 點 |
| 停用 AP 時保留原規則 | 全部原有情境 | 沒有設定 AP 的玩家完全不受影響 |

紀錄片段（`ap_chain`）：

## 點數表匯入

`scripts/import_genesys_points.py` 使用 `tools/` 的可攜式 Python，執行步驟如下：

1. 讀取 <https://www.yugioh-card.com/en/genesys/> 的表格（頁面編碼是 Windows-1252）。
2. 依序用以下方式把卡名對應成卡號：
   - 我們的卡片資料庫，包含有 alias 的卡。
   - YGOPRODeck 的現行 TCG 卡名。
   - 手動對照表。
3. 只要有任何一筆對不上就中止，不會跳過。

761 筆全部對應成功，其中幾筆需要特別處理：

| 卡名 | 處理方式 |
| --- | --- |
| Kuriboh - Multiply!、Number 39: Utopia, Emissary of Light | 透過 YGOPRODeck 的新譯名對應，原名分別是 Multiplying Kuriboh!、Utopia the Envoy of Light |
| Exstellarknight Constellar Ptolemy Ω7 | 頁面寫成「O7」，用手動對照表處理 |

## 已知限制

- **同一時點多個選發效果**：機制上每個連鎖窗口都依當下的 AP 計價，但同一時點同時觸發多個選發效果、以及必發效果排序的情況，還沒用真卡實測。
- **特殊召喚的判斷**：玩家主動的特殊召喚程序，是用「選了 spsummon 之後出現的第一個特殊召喚訊息」來確認。如果召喚程序本身的代價也會觸發特殊召喚，扣點時機可能需要再確認，目前測試卡池裡沒有這種卡。
- **AP 只檢查 0 號玩家主動的動作**：敵人沒有 AP，敵人的行動模式屬於 P5。
- **點數表沒有生效日期**：官方頁面沒有標示生效日期，所以只記錄抓取日期；官方更新時要重新執行匯入。
- **點數規則只檢查 0 號玩家**：對手牌組不檢查。
- **合法性只有點數一項**：張數上限、禁限卡表、Genesys 卡池都沒有實作。
